SDK requests and webhook subscriptions independently target **2026-08-21**. ## Known limitations and upgrade guidance

Open delegated reviews [#60](https://github.com/jojeringnax/airwallex-php-sdk/issues/60) and [#61](https://github.com/jojeringnax/airwallex-php-sdk/issues/61) cover client timing/retry configuration and item-read names. [#64](https://github.com/jojeringnax/airwallex-php-sdk/issues/64) provisionally limits Price creation to FLAT/PER_UNIT; nonmetered VOLUME/GRADUATED is a separate choice from the accepted usage-billing deferral. Composer enforces the provisional 64-bit PHP platform requirement from [PR #103](https://github.com/jojeringnax/airwallex-php-sdk/pull/103); [#101](https://github.com/jojeringnax/airwallex-php-sdk/issues/101) remains open for human review. At PR #103, platform metadata changed the SDK fingerprint. The direct Checkout correction in PR #115 changes it again to `3ab42a8d0a22da3ad2d8dac3e561ccb29747ec370f517a4258579b72ad46d9a9`; historical validation keeps its original source identity and guards. These reviews, the first-party Invoice document boundary [#95](https://github.com/jojeringnax/airwallex-php-sdk/issues/95) and the pinned private Playwright same-Document condition [#120](https://github.com/jojeringnax/airwallex-php-sdk/issues/120) stay open for human review and are not recorded as human-approved requirements. The latter requires the exact runtime/source pins and changes one scope-invalidation condition; it establishes no unchanged-DOM or JavaScript-cause guarantee.

Use the [development-source installation](usage.md#install-the-unreleased-development-source) until publication is separately authorized. Select concrete PSR implementations and explicit private environment/account credentials. Use decimal strings and persisted action IDs; reconcile ambiguous mutations before a deliberate new action. Applications own buyer authorization, private identity maps, persistence, event ordering/reconciliation, document delivery and access/grace policy. Unknown states and nullable links need explicit handling. OAuth, deferred Billing products, hosted Billing portal sessions, pause/reactivation, SDK onboarding and SDK synchronization remain outside the initial implementation boundary.

There is no previously released SDK line to migrate from. Development consumers of direct Checkout webhooks should remove string-only assumptions at the six known integer positions; [consumer guidance](consumer-examples.md#webhook-boundary) preserves exact money/unknown numbers, raw nesting and application-owned acceptance. Under [0.x compatibility policy](release-policy.md), constrain the chosen minor line; breaking changes require a minor release and migration notes, patches preserve the public contract, and only the latest minor is maintained. API-pin upgrades require official family/schema/auth/event review, refreshed fixtures and affected Sandbox examples, coordinated with webhook-subscription migration. Provider defaults never silently change the SDK pin.

#20, #28 and #42 retain unresolved implementation/evidence criteria. #43 is complete for documentation content; #44 retains eventual clean-revision artifact/candidate acceptance. Closing #25/#26 at their stated boundaries does not pass the full-scope release gates.
