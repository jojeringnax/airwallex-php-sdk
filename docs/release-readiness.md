These reviews and the first-party Invoice document boundary [#95](https://github.com/jojeringnax/airwallex-php-sdk/issues/95) stay open for human review and are not recorded as human-approved requirements.

Use the [development-source installation](usage.md#install-the-unreleased-development-source) until publication is separately authorized. Select concrete PSR implementations and explicit private environment/account credentials. Use decimal strings and persisted action IDs; reconcile ambiguous mutations before a deliberate new action. Applications own buyer authorization, private identity maps, persistence, event ordering/reconciliation, document delivery and access/grace policy. Unknown states and nullable links need explicit handling. OAuth, deferred Billing products, hosted Billing portal sessions, pause/reactivation, SDK onboarding and SDK synchronization remain outside the initial implementation boundary.

There is no previously released SDK line to migrate from. Under [0.x compatibility policy](release-policy.md), constrain the chosen minor line; breaking changes require a minor release and migration notes, patches preserve the public contract, and only the latest minor is maintained. API-pin upgrades require official family/schema/auth/event review, refreshed fixtures and affected Sandbox examples, coordinated with webhook-subscription migration. Provider defaults never silently change the SDK pin.
